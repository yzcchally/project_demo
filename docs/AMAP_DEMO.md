# 高德路线课堂演示

本页提供手机 App 内可以直接启动的入口、两组可编辑公共地点和人工核对标准。每次必须真实查询高德；下列地点不是预置结果，也不表示用户当前位置。实际成功、部分读取、失败、耗时及人工介入记录见 [AMAP_ACCEPTANCE.md](AMAP_ACCEPTANCE.md)。

## 演示前准备

1. 在 Mac 启动现有后端，手机用 USB 连接、解锁并允许调试，确认 Demo 无障碍服务开启。
2. 重新连接手机后执行 `adb reverse tcp:8000 tcp:8000`。手机需要能够联网使用高德，电脑需要能够访问已配置模型服务。
3. 安装本轮 APK并打开小银助手；高德安装包应为 `com.autonavi.minimap`。版本及支持范围见 [AMAP_TRANSIT.md](AMAP_TRANSIT.md)。
4. 先在高德本人处理首次隐私提示、必要授权或登录提示。查询路线不应强制依赖邮件账号。
5. 结束其他正在使用手机的任务。运行时由一人演示，其他人暂不点按手机，避免同时改变候选和路线页面。

普通查询不需要实际出行。除使用当前位置的专门测试外，先用明确起终点，便于课堂复现。

## 手机内的直接入口

点击首页右上角 **“演示案例”**，先通过按钮选择 **“地图查询”** 或 **“邮件案例”**。

两类都提供 **推荐／正常／异常／恢复** 筛选；切换类型时重置为该类型“推荐”。共有 19 个可见案例（T02–T20），T01 仅保留 API 兼容和备用检查。

**“演示案例 → 地图查询”** 提供 T13–T20。选用后提示词会填入首页，可在手机直接修改城市和地点，再点击“查询公交地铁路线”。地图“推荐”为 T13、T15、T18：

| 筛选 | 编号与标题 | 演示目的 |
| --- | --- | --- |
| 正常 | T13「开始高德公交地铁导航」 | 查询从广州塔地铁站到客村地铁站的路线。核验后点击「开始高德导航」并确认，看到高德显示「结束导航」即达到演示目标 |
| 正常 | T14“当前位置完整查询” | 从高德核对真实当前位置，查询到广东省博物馆；定位不可用时请本人补起点 |
| 异常 | T15“出发地不明确” | “家里”未绑定时先询问明确起点，观察后取消 |
| 异常 | T16“目的地不明确” | “我家”未绑定时先询问明确目的地，保留已提供起点，观察后取消 |
| 异常 | T17“取消路线查询” | 途中取消，检查任务状态与迟到结果处理 |
| 恢复 | T18“补充起点后继续” | 补充公共站点，在原任务继续真实查询 |
| 恢复 | T19“暂停后继续查询” | 暂停／继续后重新观察；无法安全恢复时清楚提示重查 |
| 恢复 | T20“恢复网络后重查” | 本人准备手机断网，再恢复网络发起新查询 |

正常案例不显示分步说明，一次启动完整任务；异常与恢复案例可展开 3–5 步操作。选择类型、浏览或填入案例都不会自动开始任务。T15–T20 没有故障注入元数据，使用已有澄清、取消、暂停／继续及重查能力；列为内置案例不代表本轮已经逐项真机通过。

**“演示案例 → 邮件案例”** 提供 T02–T12，再按推荐／正常／异常／恢复筛选；推荐为 T02、T04、T12。该页包含扫码发信、网页校验和任务控制等辅助案例，各卡片说明实际动作和预期结果。

也可以在首页点击 **公交 / 地铁路线**，填写城市、出发地、目的地，选择“尽量少换乘”“尽量少步行”或“高德推荐”。填写了明确出发地时，该地点优先于当前位置。邮件案例页的“正常”分类仍只保留 T02 一条完整扫码发信案例。

自然语言输入框和“说出您的需求”也可进入路线任务。语音通过现有本地转写链路识别，不要把“语音识别成功”与“路线核对成功”混为一个结果。

## 正常演示 A：明确起终点

在路线表单中填写以下公共地点，或修改路线案例提示词：

| 字段 | 内容 |
| --- | --- |
| 城市 | 广州市 |
| 出发地 | 体育西路地铁站 |
| 目的地 | 广州塔地铁站 |
| 偏好 | 尽量少换乘 |

手机指令示例：

```text
在广州市，从体育西路地铁站去广州塔地铁站，坐地铁或公交，尽量少换乘。
```

开始一次查询后，展示小银理解目标、真实打开高德、核对地点和起终点、切到公共交通、展开选中方案详情，再回小银显示路线总览和大字步骤。若有同名地点，请本人核对列表里的实际名称与地址后选择；不要让演示人员代猜院区或站点。

回小银后将线路、方向、上下车站、换乘和步行段逐项与高德详情对照，点击“朗读这条路线”。然后依次点击“第一步怎么走？”“我应该在哪一站下车？”“需要换乘几次？”，核对回答与当前方案一致。点击“查看高德详情”可以回高德核对，返回小银时结果仍应保留。

高德显示的耗时、站数、费用和步行距离随查询改变。即使开发观察曾看到某个数字，演示也必须以本次真实结果为准，不能把该数字写进代码或作为固定通过条件。

## 正常演示 B：换一组公共地点

| 字段 | 内容 |
| --- | --- |
| 城市 | 广州市 |
| 出发地 | 流花地铁站 |
| 目的地 | 广州东站地铁站 |
| 偏好 | 尽量少换乘；也可在手机选择其他偏好 |

```text
在广州市，从流花地铁站去广州东站地铁站，坐地铁或公交，尽量少换乘。
```

这组地点已完成一次真实完整查询，实际读取到 11 号线内环，详见验收记录；每次演示仍必须重新查询，不预先承诺线路、直达或换乘次数。只有本轮高德详情显示并被读取的内容才能进入结果。如果实际方案包含换乘，展示各段上车、方向、下车和换乘顺序；若是直达，如实记录，不为展示换乘而编造线路。

如果两组都返回直达，可以在同一城市改用其他明确的公共起终点，重新查询一条包含换乘的方案；是否完成混合公交／地铁验收要独立记录。

## 可选换乘演示

在同一个路线输入框修改为：

```text
在广州市，从广州塔地铁站去公园前地铁站，坐地铁或公交，选择高德推荐方案。
```

本轮真实重查读到 3 号线 → 体育西路站内换乘 → 1 号线，并验证了三张顺序卡片、1 次换乘和分别回答两段下车站。每次演示仍以新查询为准，不能把本轮 25 分钟或 145 米作为固定结果。该样本的开发失败、人工诊断与最终 74.29 秒重查记录见验收文档。

## T14：当前位置完整查询与定位澄清

在 **“演示案例 → 地图查询 → 正常”** 选择 T14，提示词为：

```text
在广州市，从当前位置去广东省博物馆，坐地铁或公交，选择高德推荐方案。
```

系统会先打开高德真实“我的位置”页面，核对地址和城市，以及系统实际定位的授权、精度、新鲜度和非模拟标志；不会从截图时间推算定位年龄。只在这些检查均通过时使用它。若小银提示无法可靠核实当前位置，请填写本人明确提供的公共起点再继续。这个澄清是预期结果；不能把“体育西路地铁站”或其他演示地点自动改名成“当前位置”。

也可以说“从家里去博物馆”。没有家庭地址绑定时必须先追问，不应直接查询一个猜测地址。对同名博物馆、分馆、院区或地铁口，用户需要明确选择本次地点。

## T15–T20：异常与恢复案例

在“地图查询 → 异常”选 **T15**，保留“从家里去广东省博物馆”，启动后应先询问明确起点；本轮只观察澄清提示，再取消。选 **T16** 时保留“从体育西路地铁站去我家”，应询问目的地并保留明确起点，再取消。不要为了继续演示把家庭地址猜成当前位置或公共站点。

**T17** 启动后等高德进入地点或路线查询，从小银通知点“取消”。回小银查看取消状态，并观察是否停止后续操作、拒绝迟到结果；已经开始的模型或系统调用可能要等待返回后才停止，应记录实际等待时间。

在“地图查询 → 恢复”选 **T18**，先保留“家里”触发澄清，再在出发地填入 **“体育西路地铁站”**，核对城市仍为广州市、目的地仍为广东省博物馆，点击 **“补充好了，继续查询”**。应在同一任务继续打开高德，回来核对路线卡片和朗读。该起点是本人补充的明确地址，不可记作 GPS 定位成功。

**T19** 使用流花地铁站到广州东站地铁站的提示词。高德打开后从通知点“暂停”，等待几秒并保持页面不变，再点“继续”。规则主导查询会在当前调用返回后废弃旧页面，在同一查询内最多自动重新采集一次；重新核对地点，不能续点旧控件。动作预算不补满，自动钉钉分享暂停，可核对结果后主动分享；第二次中断、未知页面或预算不足仍应清楚停止并允许重新查询。体育西路至广州塔的同类场景已通过 API 暂停/继续真机验收；本路线及通知按钮应按现场结果另记。

**T20** 需要本人在手机关闭 Wi-Fi 和移动数据，电脑后端保持联网，USB 连接保持正常。开始后观察真实网络错误；高德可能使用缓存继续返回结果，此时如实记录 **“故障未复现”**。本人恢复手机网络并确认高德能搜索后，回小银等待旧任务停止，再点“重新查询”。核对新的查询时间及实际结果，成功、部分读取或失败分别记录；不能把旧结果当成新查询成功。小银不会替您开关网络，也不会自动注入此故障。

## 暂停、取消与恢复演示

| 场景 | 手机操作 | 应观察到的结果 |
| --- | --- | --- |
| 查询中暂停 | 从小银或后台通知点“暂停” | 在动作检查点暂停；没有新的有效结果被当作完成 |
| 暂停后继续 | 保持高德页面可观察，点“继续” | 同一查询最多自动重新采集一次，不复用旧控件或旧地点确认；第二次中断或无法核对时清楚停止并允许重新查询 |
| 查询中取消 | 点“取消” | 已在进行中的调用可能等待返回；随后不能继续点按或提交旧路线。记录实际取消延迟 |
| 模型或网络失败 | 查看小银失败原因，再点“重新查询” | 新查询生成新的查询标识并重新取得设备操作权；不能把旧数据当成新查询成功 |
| 改为少步行 | 点“换一个步行更少的方案” | 真实重新进入高德查询或比较本次实际候选，保留来源；不能只修改讲解文字 |
| 部分详情不可读 | 核对 PARTIAL 提示及有效卡片 | 显示缺失方向、上下车站等；不显示完整成功，不让模型补猜 |

取消是协作式的，不承诺立即中断已经开始的模型或系统调用。演示时说明“正在等待当前调用返回”比反复点击更准确。

## 课堂展示节奏

正常演示以约 2–3 分钟为目标，实际达标情况必须按测量记录：

1. 简短说明出发地、目的地、偏好和电脑／USB 部署方式。
2. 一次启动，观察高德的真实页面变化，必要时本人选择地点。
3. 返回小银，展示总览、逐段卡片及一段中文朗读。
4. 点击一个即时追问，回高德核对来源，再回小银保留结果。
5. 若时间允许，追加一次暂停／继续或取消，展示明确的任务状态。

需要同时展示正常、异常和恢复时，可从 **“演示案例 → 地图查询 → 推荐”** 依次选 **T13 → T15 → T18**：T13 一次启动完整查询；T15 展示起点澄清后取消；T18 再开始一条任务并补起点继续。每轮结束或取消后再选下一条。邮件展示另从“邮件案例 → 推荐”选择 T02 → T04 → T12，两类案例不混在同一列表。

可把两条查询分别演示并记录，不需要把异常、定位、全部追问和两条路线都强塞进同一个 3 分钟片段。T14 定位、T19 暂停恢复和 T20 断网重查各自单独验收；以真实日志和 [验收记录](AMAP_ACCEPTANCE.md) 为准，不因案例卡片已提供就填写“通过”。

## 每次验收填写

| 项目 | 记录内容 |
| --- | --- |
| 设备和软件 | 手机型号、Android 版本、高德版本、APK／代码版本 |
| 输入 | 明确起点、终点、城市、偏好；是否请求真实当前位置 |
| 来源 | 任务 ID、查询 ID、查询时间、选中方案 ID、证据目录 |
| 结果 | COMPLETE / PARTIAL / NO_ROUTE / FAILED；缺失字段及核对情况 |
| 路线对照 | 线路、方向、上下车站、步行、换乘、时间等实际可见字段 |
| 人工介入 | 地点选择、授权、澄清属于哪一步；是否由开发者手动修复或点击推进 |
| 耗时 | 从本次启动到结果展示的总时长；是否包含人工等待 |
| 控制 | 暂停、继续、取消的操作时间及后续是否仍有旧动作 |

两条路线、当前位置成功、定位澄清、混合公交地铁、失败处理应分别记录。自动化替身、离线屏幕或开发观察不能写成完整真机端到端通过。
