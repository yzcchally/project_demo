# AutoGLM 高德 GUI Agent

本模式将正式 `plan_transit` 任务接入“观察截图 → AutoGLM 决定下一动作 → 独立检查 → 手机执行 → 新观察”的闭环。保留原有 `rules` 模式；`autoglm` 不是规则失败后的备用模型。正常查询中的 Launch、Tap、Type、Swipe、Back、Wait 由本轮模型响应决定，检查通过后直接由现有设备层执行。Finish 只申请进入路线核验。

## 配置与启动

在本机被 Git 忽略的 `.env` 中设置：

```dotenv
SILVERGUIDE_TRANSIT_EXECUTOR=autoglm
SILVERGUIDE_AUTOGLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4
SILVERGUIDE_AUTOGLM_MODEL=autoglm-phone
SILVERGUIDE_AUTOGLM_API_KEY=
```

最后一行由本人在本机填写，不把真实密钥贴到文档或提交到 Git。官方配置依据 [Open-AutoGLM README](https://github.com/zai-org/Open-AutoGLM#readme)。API 地址与模型名称可切换到兼容服务；云端模型的具体实现由服务商决定，不将其等同于公开的某个 9B 权重。使用现有 OpenAI 兼容客户端，无需在本机下载 AutoGLM GPU 权重，也不运行独立的上游 `PhoneAgent.run()` / `step()`。

AutoGLM 与 `DEEPSEEK_API_KEY`、`SILVERGUIDE_TEXT_MODEL`、`SILVERGUIDE_VISION_MODEL` 相互独立。自然语言理解和按需的路线事实提取继续使用现有 ModelGateway；新增密钥只用于高德 GUI 动作决策。缺少 AutoGLM 密钥时明确失败，不调用原规则查询作为替代。恢复规则模式只需将 `SILVERGUIDE_TRANSIT_EXECUTOR` 设为 `rules`。

1. 完成或取消当前任务，停止旧后端后修改配置，再运行 `./start_backend.command`。
2. 用 USB 连接并解锁安卓手机，允许 USB 调试，开启 Demo 无障碍服务，确保已安装小银和高德。
3. 按现有启动说明执行 `adb reverse tcp:8000 tcp:8000`。
4. 从小银输入公开地点需求，例如“在广州市，从体育西路地铁站去广州塔地铁站，查询公共交通，尽量少换乘。”，或使用正常地图案例。
5. 查看任务快照／事件中的 `transit_executor`，必须为 `autoglm`。模型动作进度复用原有 App 与 WebSocket 展示。

每个查询创建时保存执行模式。暂停、继续、地点澄清及地点选择恢复均沿用该查询的模式和设备 worker；修改环境变量不会令进行中的任务换执行器。显式重新查询会生成新的 `query_id` 并采用当前后端配置，旧结果连同旧模式保留。旧版本没有模式字段的任务按 `rules` 解释。更改 `.env` 后须重启后端，配置文件不是实时开关。

## 动作协议与真实执行

模型请求包含本次自然语言路线需求、任务和查询标识、当前 App／屏幕尺寸及有限的实际执行历史。有历史时，首条 user 消息保存本轮完整路线需求 `natural_task`，不使用当前子目标重新解释既有动作所属的任务；其后保留 assistant 的实际单个 `do(...)` 及执行结果。每轮最新 user 消息只包含一张当前真实 PNG 截图和一个完整文字块；该文字块承载 `current_goal`、本轮任务／界面 JSON，以及已有的拒绝反馈和上步实际结果，JSON 内也保留 `current_goal`。无效、缺参数或未确认执行的历史不补造为动作，也不带回历史截图或原始思维过程。使用官方兼容的多模态消息及 `do(...)` / `finish(...)` 动作协议，而不是 ModelGateway 的 JSON Schema 草稿动作格式。

界面信息包括独立读取的地点字段与缺失项、实际筛选、详情帧数、可见终点和输入框聚焦情况。`screen_info.route_inputs` 保存已识别原生起终点框的实际文字，`route_inputs_match` 标记与本轮需求是否一致，`observed_public_transit` 来自实际公共交通选项的选中状态。地点核对完成后，当前目标会反馈已识别路线页中仍不匹配的起终点、尚未确认的公共交通模式或未实际应用的偏好；这些条件核对后才提示选择方案。起终点选择页中，若当前字段文字正确、仍待确认，且当前只有一个名称符合已核对主站点的候选，目标会提示模型确认该主站点，避免重复输入或选到站口。反馈不替模型选坐标或执行动作。用户选择的地点单独标记，不冒充已读取的地点证据。

解析器只接受一个完整、受支持的动作；只解析有限语法，不执行模型代码。未知字段、多动作、越界坐标或任意调用表达式均拒绝。`ProtocolError/invalid_syntax` 的回复不生成动作或下发设备，执行器最多重新观察并请求两次新决策；超过上限或其他协议错误则停止。日志只记录固定白名单错误类型和诊断枚举，不保存原始回复或错误原文。仅当固定枚举识别出 Finish 字符串未闭合，才反馈简短协议格式示例；仍由模型根据当前页面决定是否请求核验，程序不修补无效回复。对客户端识别为 `IncompleteResponse` 的 API `length` 截断，执行器也允许最多两次获取新截图并重新决策；截断文本完全不进入动作解析、不下发设备，也不补成已执行历史。其他异常结束或超过重决策上限仍停止，取消及原步骤／时间预算继续生效。Tap 使用整数 0–999（1000 本身无效），按 int(value / 1000 * 当前屏幕宽或高) 换算后，还必须落在可独立核对的当前候选上；坐标在屏幕范围内本身不构成许可。

| 动作 | 当前约束 |
| --- | --- |
| Launch | 只打开本次授权的高德包。 |
| Tap | 必须匹配当前高德页面中独立识别的允许控件／主地点标题；隐藏、歧义、重叠或不受支持目标不执行，有限重新决策条件见下文。 |
| Type | 使用现有高德无障碍输入桥，当前输入框及输入内容必须对应本次明确需求或已经确认的地点。 |
| Swipe | 限定在可核对的纵向查询容器，或已证明的原生公交偏好栏水平区域；检查原手势坐标、方向、边界和全路径覆盖。 |
| Back | 仅在可核对的高德任务上下文中返回。 |
| Wait | 有界等待，并继续执行取消检查。 |
| Finish | 结束动作决策，使用本轮真实页面和现有提取／验证流程判断结果。 |
| Take_over / 人工协助请求 | 明确停止并说明需要本人核对后重新查询；不作为成功，也不自行登录或授权。 |

程序不会把模型自己声明的角色当作独立授权证据。动作前重新读取页面，检查截图尺寸、方向、当前 App、页面内容和上下文 epoch；暂停恢复或模型请求期间页面变化会废弃旧动作。动作后再次读取真实页面，实际结果进入下一轮模型上下文。同动作在无进展页面重复达到上限会停止。原始响应中的推理过程不作为执行代码，也不默认写日志。

默认模型步骤预算 30、总执行预算 240 秒、单次 API 预算 35 秒、历史最多 8 条。可通过 `SILVERGUIDE_AUTOGLM_MAX_STEPS`、`SILVERGUIDE_AUTOGLM_TOTAL_SECONDS`、`SILVERGUIDE_AUTOGLM_TIMEOUT`、`SILVERGUIDE_AUTOGLM_HISTORY_LIMIT` 调整，允许范围见 `.env.example`。暂停／系统或网络调用可能使墙钟耗时超过某个局部预算；取消是协作检查，不是撤回已发出的系统调用。

本轮本机验收将 `SILVERGUIDE_AUTOGLM_HISTORY_LIMIT` 调为 1，源代码默认仍为 8；这是本地调参，保留原有消息角色及实际动作历史格式。单轮请求实验未用于正式客户端。保存帧探针同时涉及历史设置与目标反馈等改动，不能据一次正确提案认定某项调参是唯一原因。

当前采用保守的一致性检查：Tap、Type、Swipe、Back、Finish 绑定完整界面树及窗口，桥接 nonce 和采集时间不参与内容比较。Pillow 逐像素比较只允许有独立边界的少量变化：由 Android InsetsSource 报告且不含目标坐标的顶部状态栏；同一已获准聚焦输入框内的细窄均匀光标；同一已识别加载弹窗的小型原生转圈区域，且仅用于 Back 或该弹窗取消按钮；已识别路线卡的实时到站小图标。到站图标例外用于两帧均独立核实的同一起终点编辑入口、本轮要求的偏好按钮 Tap，或已核实的 `preference_scroll` 水平手势。完整原生树和窗口必须一致，公共交通必须已选中，到站标签只能是“即将进站”或有效 24 小时格式的 `预计HH:MM进站`，前后文字也必须不变。

同一原生结构路径的规范路线卡 Tap 还可使用该卡自身的小图标例外，但须同时具备当前 `query_id`、实际应用的本轮偏好、当前查询的 `place_detail`／`location` 地点字段来源，以及实际匹配的起终点输入栏。点击不能落在图标上，不能忽略另一张卡的图标；筛选手势路径也不能穿过被忽略的图标区域。这些检查只允许该小图标动画，不直接证明路线完整。其他偏好、Type、Finish 或其他 Swipe 不能借用此例外。

其余像素必须完全一致，没有忽略整个输入框、键盘、地图或路线卡。路线文字、控件、窗口、尺寸、方向、前台或 epoch 变化仍废弃旧提案，包含不可见路线 ETA 文字更新。不依赖屏幕目标的 Launch、Wait、人工协助请求可忽略内容刷新，但仍须匹配全局上下文，Launch 仍只能打开高德。未识别的动画／光标主题可能继续导致保守废弃和预算耗尽。

模型每轮收到当前还缺哪些地点来源，以及真实聚焦框、现有文字和允许输入。字段已经明确但模型提出不一致文本时，拒绝该文本并最多允许两次重新观察、重新决策；不会替模型更换文字。两端地点证据不足时，已识别的路线入口先反馈缺项，最多重新决策两次，不替模型点击搜索。可独立识别的方案卡若起终点或实际应用的偏好不符，返回 `route_prerequisite_missing`，最多重新决策两次；该方案卡点击没有执行，也不算已选择方案。

坐标没有命中已识别控件时，只有页面存在可独立核对的原生候选，才可针对 `unrecognized_target` 最多重新决策两次。在前后全局上下文相同的情况下，若模型所见原帧已独立判定该点为 `UnrecognizedTarget`，且该帧有已核对候选，可以先记录拒绝并反馈，避免无关动画使无效提案一直只被废弃。此分支只拒绝，不执行、不重定位；可执行提案仍须通过新帧一致性与独立定位。无法提供候选则停止；外部应用覆盖、敏感目标、重叠或歧义等校验失败不进入此重试。所有重新决策均消耗原步骤和时间预算，未执行的提案不会成为已执行历史。

`screen_info.native_control_hints` 提供当前截图中至多 16 个可独立核对的原生控件文字、角色、像素 `bounds` 和 `normalized_bounds`。归一化范围两端均包含在内，坐标为 0–999；使用整数上取整反算，保证按屏幕尺寸转换回像素后仍落在原控件内。提示只给范围，不返回建议中心点、不发出动作，也不替模型修改其输出坐标。当前偏好目标可唯一核对时，会先反馈该控件实际可见的归一化范围；若目标贴着最右边界、归一化横向跨度小于 100，且已有核实的水平筛选栏，当前目标先要求让标签完整显示，再应用筛选，仍由模型选择动作和坐标。每个准备执行的提案仍须在新帧上重新定位、检查覆盖层并核对任务来源。已适配的主地点文字区域与详情顶部关闭按钮依赖实际原生结构；站口、旁侧路线快捷入口和未知控件不会随整张卡片一起获准。

`screen_info.horizontal_scroll_regions` 只提供已核实原生公交筛选栏：`normalized_bounds` 是起手子栏，`gesture_normalized_bounds` 是同一已证明原生行的完整手势范围。该区域须来自 `SpringHorizontalScrollView`，实际公共交通已选中、起终点匹配，且六个偏好标签和“现在出发”所在行的原生结构均符合已适配布局。手势必须从子栏安全内侧开始，具有明确长度且接近水平；左拖的终点可离开子栏，结束在同一行的安全内侧，但不能从左侧时间控件起手或越出该行。程序保留模型原手势坐标，全路径遇到外部应用或未知覆盖则拒绝。滑动后重新观察并定位标签，其他水平区域不因此获准。

`screen_info.current_place` 只在已识别地点详情页中提供：地点名称和城市都必须引用当前这一帧的证据，证据属于当前 `query_id`，且只能唯一对应本轮一端已核对地点；缓存地点不代表当前所见。`available_navigation_actions` 中的 Back 也须先通过当前页面的 `resolve_action(Back)` 检查。仅当当前实际显示的是已核对的另一端详情、下一端仍待核对，并且 `native_control_hints` 明确为空列表时，目标才建议模型用非坐标 Back 返回后查看新截图；缺失提示、未知页面或旧地点均不触发此建议。程序不会自动返回、猜测工具栏按钮或替模型导航。

已适配高德 15.13 的首页“公交地铁”、地点搜索文字区域及公共交通页原生／匿名双输入栏，通过真实资源标识、祖先结构、可见文字与边界共同识别。首页搜索栏可以是默认提示，也可以保留其他旧普通地点；严格的唯一原生入口、文字与描述及祖先结构必须一致，二维码和语音按钮不属于搜索点击区域。这里只允许打开编辑页，旧地点不会因此成为允许输入或本轮地点证据。单框地点编辑页与双框路线编辑页分别识别，不依赖上次点击记忆给任意 EditText 指定角色；Type 仍要求当前唯一、启用且已聚焦的获准输入框，隐藏或禁用的占位框不算实际输入目标。

搜索页可通过唯一、与本轮明确地点匹配的历史主地点控件打开地点；历史本身不提供本查询的地址、城市或路线证据，必须重新读取当前地点页面。空关键词编辑页内已适配的两排原生快捷地点条目也只作为导航入口：必须唯一且完整名称符合本轮地点，该地点已有已确认／已读取的地址时，不使用这种缺少地址的入口。快捷条目不会提供地点事实，其他类别、家／公司或名称不符的站口不会随同获准。

已识别单框编辑页中的联想建议不会被提升为正式地点证据或直接触发人工选点。正式搜索结果存在歧义时，沿用当前查询绑定的候选选择；已输入关键词后残留的旧历史不会充当新结果，历史条目无法核实已确认地址时不采用该入口。打车、历史路线快捷键、收藏、删除、扫码和语音不因此获准。

搜索标题与本轮搜索词的归属比较复用 `task_search_text_matches()`：仅认可字面 `(地铁站)`／`（地铁站）` 格式，以及最多一个与本轮完全一致、以“市”结尾的行政市名前缀差异。它保留“地铁站”和站口等名称内容，不把“广州塔”与“广州塔地铁站”、主站与站口、其他城市或校区视为同一搜索词，也不放宽 Type 的允许文本或代替地点证据。

地点事实可从已识别的完整详情或底部紧凑详情主标题区读取。原生主标题旁的精确“刚刚浏览”标签在搜索条目和主详情中一致支持，标签本身不提供地点名称或城市证据，也不接受任意附加文字。主详情以外的站口条目、相似地点推荐及其他列表项不能补作主地点名称、城市或地址。固定页脚“路线”按钮仅在本次地点身份及页脚结构均可核对时执行；已知按钮缺少原生边界时，可用本轮 Apple Vision OCR 定位唯一高置信度页脚，并再次核对截图和地点。匿名输入页只认可已观察到的背景与输入布局，其他覆盖层不因空白而自动获准。尚未支持系统键盘上的图形搜索键；未知图片控件仍可能不支持，本模式不是任意高德版本的通用控制器。

路线入口与主页公交入口使用同一地点证据前置条件：先核对两端所需字段，缺项时反馈给模型重新观察、重新决定，不能从另一个地点直接跳过来源核对。高德受保护读取的一次观察最多请求两次，每次前后检查取消及上下文，外层不再额外重试。手机端保留不可见边界节点但跳过其子树；边界仍检查密码与包名，可见零边界标签继续保留。此优化不把不可见内容当作证据，已有 nonce、窗口、新鲜度和大小限制继续生效。`SilverGuideTransit` 诊断日志仅含读取阶段、节点数和耗时，不输出地点或界面文本。

对已识别的原生“正在加载”弹窗，模型收到实际等待时长，15 秒后提示其考虑 Back 或取消后重新搜索。弹窗存在时只允许有界等待、返回、当前原生取消按钮或人工协助，禁止点击底页、输入和 Finish，也不读取被遮挡的地点事实。模型误提底页动作时最多重新决策两次；同一弹窗持续 60 秒则停止，不由程序自动取消。只有动作确实下发且新观察确认弹窗消失，才将“已取消加载”反馈给模型。该支持依赖已验证的原生结构，不扩大到任意转圈或关闭图标。

## 证据与结果

AutoGLM 返回的文字不是路线证据。执行器保留本查询的真实地点页面、已选择方案、截图与 XML；Finish 后复用原生优先的事实提取和独立 `validate_result()`。关键字段、起终点、当前方案或详情采集不足时只能是 PARTIAL／FAILED；真实无公共交通提示才支持 NO_ROUTE。不会直接采纳模型声称的 COMPLETE，也不会从旧查询补事实。

采集路线详情时，`AmapDevice._observe()` 使用已过滤祖先隐藏、禁用或其他应用分支的节点，判定实际页面并生成详情证据文字；等待进入详情不等于已经取得详情，旧列表也不会因不可见标记而变成详情页。完整原始 XML 仍保留在本机，不把过滤后的文字当作改写界面树的许可。选择方案前，起终点各须有唯一可见、启用的原生输入栏，文字仍绑定本轮已读取并核对的实际 POI 名称；核对支持高德显示本轮配置的精确行政市名前缀，不改用原始泛称或其他请求别名放行。

用户明确起点优先于“我的位置”。当前位置仍需真实地址、城市、权限、定位新鲜度、精度和非模拟来源检查；定位不可核实时要求补起点。同名、校区、分馆等歧义继续通过现有 `query_id`／nonce／候选集合绑定的地点选择处理，只有本人确认的当前候选才能替换输入别名，不自动把地铁站改成某个站口。恢复选择后先重新观察并核对所选名称与地址，不重放不明副作用。进程重启后的未完成任务进入 `interrupted`，需要明确的新查询，不自动重启模型动作。

模型操作与原规则任务使用同一手机 worker、暂停、取消和互斥检查。邮件、扫码及浏览器原流程不切换到 AutoGLM。路线卡片、朗读和三个路线追问继续使用已验证的结构化结果。“查看高德详情”使用现有来源查看器核对本次高德详情，不等于再次执行 rules 查询。

选作路线起点及 Finish 前会再次核对定位新鲜度和健康，不把后来的定位时间附到旧地址证据上。NO_ROUTE 也须有实际公共交通操作、匹配起终点和本轮无方案提示，不能只采用模型的文字判断。

## 查看记录

HTTP：`GET /api/tasks/{task_id}` 与 `GET /api/tasks/{task_id}/events`。路线任务字段包括：

- `transit_executor`：本查询实际选择的 `rules` 或 `autoglm`；
- `transit_agent_step`、`transit_agent_last_action`：AutoGLM 步骤和精简动作元数据；
- `transit_agent_events`：最近至多 20 条摘要；
- 原有 `transit_result`、`route_verified`、`query_id`：独立核验后的结果与来源。

本地证据位于 `.run/workflows/{task_id}/transit/{query_id}/`。`autoglm-actions.jsonl` 将动作类型、模型建议坐标、实际坐标、通过／拒绝状态及操作前后观察标识关联起来；`autoglm-model-calls.jsonl` 记录 API 模型、成功状态、耗时与观察标识；原始模型思维过程、API Key 和完整输入文本不写入这些元数据日志。XML／截图另存为本机证据，可能含位置或私人信息，沿用 `.run/` 忽略规则，不能提交 Git。保留任务和发送幂等记录，清理屏幕证据前先预览并确认实际文件范围。

## 常见失败与验收口径

| 情况 | 实际处理 |
| --- | --- |
| 密钥缺失、认证失败或模型服务超时 | 明确提示 AutoGLM 配置／API 错误，停止本轮，不切换 rules。 |
| 模型回复不完整 | 不解析或执行残片；仅 `length` 对应的 `IncompleteResponse` 允许最多两次新观察重决策，其他异常结束或重试耗尽则停止。 |
| USB 断开、锁屏、无障碍／Provider 不可用 | 由现有设备预检／观察失败明确报告，重新连接后由本人重查。 |
| 高德显示“网络不佳”，系统却已联网 | 保留高德查询失败；整机联网检查不能代替应用搜索验证，需在高德手动确认搜索和完整地点详情可用后重查。 |
| 多动作、未知字段、坐标异常、页面变化 | 拒绝／废弃该动作，不点屏幕。 |
| 当前提案无法独立定位 | 不执行；仅在当前存在已核对原生候选时有限重新决策，否则停止，不声称适配任意高德页面。 |
| 模型 Finish，但无选中方案或关键路线事实 | 独立验证失败或部分读取，不标记 `route_verified=true`。 |
| 模型请求接管、登录或权限操作 | 停止并提示人工协助，不代替本人验证。 |

离线回归使用模型与设备替身，证明不同观察可驱动不同的实际动作调用，以及取消、过期、模式隔离和结果验证。可运行：

```bash
.venv/bin/python -m pytest backend -q
```

离线替身通过不代表真实 API／手机成功。实际测试数量、API 调用、真机动作、人工协助、耗时和最终路线核验结论统一记录在 [AMAP_ACCEPTANCE.md](AMAP_ACCEPTANCE.md)，按执行模式和本次查询区分。既有 rules 历史不能记作 AutoGLM 验收，接口或部分动作成功也不能代替完整路线成功。本模式只支持受约束的已适配高德候选，未知图片按钮或当前树无法唯一定位的控件仍可能被拒绝。

## 外部服务与来源

AutoGLM API 会收到本轮需求中的地点、当前手机截图、必要界面信息和有限执行历史；原有 DeepSeek 调用仍可能收到理解或事实提取所需数据。使用本地 ADB、OCR 和语音不等于这些模型请求都留在本机。课堂测试应使用公开地点与无私人内容页面。

协议依据 [Open-AutoGLM 官方项目](https://github.com/zai-org/Open-AutoGLM)，本项目独立实现解析、受限执行和任务集成，没有直接启动上游自动操作循环。上游许可为 Apache-2.0，实际协议参考版本及来源标记见 `backend/autoglm/`；复制上游实现时需保留相应许可与归属。
