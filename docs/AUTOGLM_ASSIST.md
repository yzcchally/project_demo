# 高德规则流程中的 AutoGLM 辅助

此功能使用既有高德规则流程作为主流程：自然语言解析、地点核对、路线操作、真实页面读取以及独立结果验证仍由 SilverGuide 完成。规则正常找到控件时不调用 AutoGLM。第一版只在路线页的**公共交通入口**经过有限观察仍无法定位时，允许模型提供一个候选点击；路线入口、路线偏好和其他操作暂不使用此辅助。能由原生文字可靠识别的已知别名先由规则处理。

## 本机配置和启动

在本机 `.env` 中配置，密钥只保存在本机，不写入仓库或聊天：

```dotenv
SILVERGUIDE_TRANSIT_EXECUTOR=rules
SILVERGUIDE_AUTOGLM_ASSIST_ENABLED=true
SILVERGUIDE_AUTOGLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4
SILVERGUIDE_AUTOGLM_MODEL=autoglm-phone
SILVERGUIDE_AUTOGLM_API_KEY=在本机填写
SILVERGUIDE_AUTOGLM_MAX_CALLS=2
SILVERGUIDE_AUTOGLM_TIMEOUT=20
```

辅助开关默认为 `false`，次数是每次查询的上限，超时单位为秒，并受本轮查询剩余时间约束；规则能完成时不要求 AutoGLM 密钥。配置变更后重启后端。在 Mac 上运行 `./start_backend.command`；连接、解锁手机，允许 USB 调试并开启 Demo 无障碍服务；手机重新连接后运行 `adb reverse tcp:8000 tcp:8000`，然后从小银 App 发起公交／地铁查询。

`SILVERGUIDE_TRANSIT_EXECUTOR=autoglm` 是先前保留的独立实验模式，它让模型持续决策，并不是本文描述的规则主导辅助。新功能请保持 `rules`，再单独打开辅助开关；不得把两个模式的验收结果混为一谈。旧模式的实现和历史见 [AutoGLM 高德 GUI Agent](AUTOGLM_TRANSIT.md)。

## 辅助的边界

辅助入口只处理明确的控件缺失，其他错误沿原路径返回。手机断开、页面不符、桥接异常、网络问题、取消、暂停后的上下文变化或预算耗尽不会被当作控件缺失。辅助使用当前真实截图及该步骤的有限候选，模型只可建议一个 `Tap`；不能启动 App、输入、滑动、返回或决定路线结果。

模型坐标经过严格协议和范围检查，再与当前页面独立识别的公交候选匹配；操作前重读页面并检查任务、查询标识、前台应用、屏幕、目标与上下文是否仍然一致。不可信或重叠目标不会执行。合格的点击通过现有设备控制链执行，随后重新观察并检查本步骤后置条件；辅助处理过该步骤后，原流程不会再点击一次。最终路线事实必须来自本次真实高德页面，并由原验证器分类，不以模型的文本或一次点击代替验证。

目前候选必须能够从当前原生界面独立识别；公共交通入口尚未实现 OCR 候选辅助。很多真实的控件缺失情况因此无法得到可信候选，系统会停止并提示用户，不会为了触发模型而发送没有可验证目标的截图。受控触发的成功也不能证明任意地图版本或未知图形控件均已适配。

截图可能包含个人信息并会发送给配置的模型服务提供方；请求仅附当前步骤所需的有限信息。请使用公开地点进行演示，并留意屏幕上可能出现的私人内容。

## 日志和受控验收

每次查询的本地证据目录为 `.run/workflows/{task_id}/transit/{query_id}/`。辅助发生时，`autoglm-assist.jsonl` 记录触发方式、请求、建议、实际操作和后置检查等状态；`autoglm-model-calls.jsonl` 记录模型调用元数据。截图和界面 XML 是本机证据，不应提交 Git；日志不保存密钥或原始模型思维过程。

没有辅助日志且无模型调用的正常规则任务，与辅助真实触发的任务分别记录。为了真机验收，在辅助已启用的情况下，可临时在后端进程配置 `SILVERGUIDE_AUTOGLM_ASSIST_TEST_MISS=transit`，只对当前查询一次已找到的公共交通控件模拟规则查找失败。仍使用真实屏幕、模型响应、动作检查、手机操作和后置验证；日志标注 `controlled_test_miss`，不能描述为真实高德故障。测试后移除该开关并重启后端。

自动化测试和真实设备验收结果应分别记录。既有全程 AutoGLM 真机成功不能作为本辅助模式真机通过的证明；详细记录见 [高德验收记录](AMAP_ACCEPTANCE.md)。
