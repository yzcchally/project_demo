## 答辩时怎样展示模型输入、输出和程序的动作

下面是**脱敏示例**，不是实时 API 回包。端点由环境配置，代码使用兼容接口 `chat.completions.create`，要求按对应 JSON Schema 返回结果。

1. **理解任务**。请求包含用户指令和已知称呼（不靠模型猜邮箱）：

   ```json
   {"instruction":"帮我扫二维码，把网页链接发给社区联系人","known_aliases":["家人"]}
   ```

   ```json
   {"task_type":"scan_and_share","recipient_alias":"社区联系人","recipient_address":"","subject":"网页分享","body":"","url":"","transit":null}
   ```

   程序找不到称呼对应的邮箱，就进入 `needs_clarification`。填写邮箱后才继续，不能把示例里的空地址作为发信目标。

2. **理解屏幕、提出动作**。准备草稿时输入阶段、当前控件候选、期望草稿及可用截图（下方省略其余候选和截图）：

   ```json
   {"stage":"prepare_email","candidates":[{"target_id":"a1b2c3d4","role":"subject","text":""}],"expected_draft":{"recipient":"example@example.org","subject":"网页分享","body":"请查看 https://example.org/","url":"https://example.org/"}}
   ```

   ```json
   {"page":"composer","actions":[{"action":"enter_text","target_id":"a1b2c3d4","role":"subject","text":"网页分享"}],"explanation":"主题为空，建议填写已指定的主题。"}
   ```

   程序验证角色、当前候选和填写内容，在真实界面执行后回读草稿。模型不能借动作建议代替用户批准发信。地图单独用 `TransitScreenDecision` 识别界面；需模型提取路线时，以 `TransitResult` 返回事实及证据引用，用独立校验判断完整度。

3. **证据分开出示**。在展示机中查看 `.run/models-log/calls.jsonl` 的阶段、模型、输入哈希和耗时；邮件任务目录中的 `decisions.jsonl` 可查看实际建议和接受／拦截结果。用本轮 `events.jsonl`、动作文件、回读结果和恢复记录证明程序做了什么。它们不等于完整模型请求／回包；展示前检查个人地址和屏幕内容。

## 真机验收顺序

1. **正常扫码链（T02）**：选择内置扫码或打开首页“使用手机自带扫码工具”。走外部扫码时，在小银等待二维码后切到系统相机或扫码工具，扫描 [测试 QR](fixtures/share-link-qr.png)，在结果或网页菜单选择分享→Demo→核对网址。若相机只能打开链接，可由浏览器分享当前的网址；这仍需人工核对，不能称为系统自动取到扫码结果。遇到不提供单独链接的厂商工具，先记录兼容缺口，再用内置扫码继续。验证浏览器核对、原生草稿回读、用户确认前不发送。末尾由适当授权的演示人员用测试邮箱验证实际发送和收件。
2. **真实切出及恢复（T12）**：选用 T12、扫码、观察系统切到主屏一次，记录恢复到同一草稿和再次核对，首轮取消并确认发送数为 0。需要展示恢复后完整发信时，另起一轮，由本人批准，一次发送后核对已发送记录与收件箱。
3. **弹窗和动作失败**：按 [异常恢复测试案例](RECOVERY_TEST_CASES.md) 分别重现已知非敏感弹窗、短暂加载和错误／缺失目标。记录是否复现、实际动作、故障前后证据。未复现不可记通过；未知或敏感窗口停下属于安全处理。
4. **地图到微信**：用已知公开车站查询真实高德方案；在小银结果页点“分享路线到微信”，查看查询时间、车站、分步交通和缺失项，核对已省略详细起终点；进入微信选择“文件传输助手”，由本人发送测试内容并核对消息。若微信不接收，试“复制路线文字”，再在文件传输助手粘贴。
5. **离线联系人**：后端关闭时点“联系家人”，用虚构号码 5550123 保存、关闭重开、二次确认打开系统拨号页、不拨出并返回，再编辑或清空。真拨号依赖手机通信服务；离线可用指保存、读取和预填拨号页。

每次注明新 APK 版本、手机和相关应用版本、测试任务 ID、实际结果与证据。Windows 模拟器无法代替华为浏览器／华为邮件、厂商扫码和微信最终交付的真机验收；高德部分截图定位的 macOS 回退也需要在兼容环境验证。

## 本轮验证结果

- Windows 后端：644 项测试及 13 个子测试通过，包含默认文件编码下的中文日志与 XML、过期扫码标识、外部链接来源和扫码后同一任务的草稿恢复。
- Android：Debug APK 构建成功，37 项 JVM 测试通过；Pixel API 36 模拟器上，4 项路线分享仪器测试通过。
- 模拟器实际打开新版：冷启动与已打开时都能接收系统分享；确认后将 HTTPS 链接填到表单，普通 HTTP 不接收；后端关闭时保存并重新读到虚构家人，取消拨号确认后仍可查看，确认则打开系统电话页且号码为 5550123。没有拨出，测试资料已清空。
- 尚未进行：使用任一目标厂商扫码器完成外部分享、T12 恢复后实际发送并收件、真实原生弹窗恢复、在微信文件传输助手中实际发送并核对。这些结论不得从本轮设备替身或模拟器结果推定。
