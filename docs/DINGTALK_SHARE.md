# 高德路线自动分享到本人钉钉文件助手

只对用户明确要求“查询后发送到自己的钉钉文件助手”的地图任务尝试自动分享。普通地图查询仍按原有流程结束。路线必须来自本次任务和查询，且被独立校验为 `COMPLETE`、`route_verified=true`；分享正文由已验证的路线分段确定性生成，附本次查询标记，不使用模型猜测路线或收件人。

程序在手机打开钉钉的文本分享页，读取受保护的前台无障碍树，仅选择页面中唯一有“我（…）”和同一行“文件助手”标识的会话，再核对发送确认弹窗的收件人显示名和完整正文。确认通过后，先持久记录一次发送尝试，再重新核对并最多点击一次“发送”。页面变化、任务停止、桥接失败或内容无法核对时不会盲点。

路线正文采用版本化格式。旧任务没有记录版本时仍按 v1 原文核验；新任务使用 v2，列出本次已读取的步行段距离与时间、乘车站数以及可核实的总览。缺失信息不会从总览推算或补猜；只有实际证据支持时才能说明筛选偏好已生效。未知版本拒绝发送和自动核验。

发送后可有界地进入本人会话进行只读核验：要求同一显示名、完整正文和本轮查询标记，且该条消息的状态明确显示“已读”或“已送达”。无法独立确认时，状态为 `unknown`，只允许后续核验，不自动重发；重新查询会产生新的查询编号，不复用旧正文。屏幕上出现已读或已送达，是当前钉钉界面的证据，并非钉钉服务器提供的独立送达回执。

App 的“演示案例 → 地图查询 → 正常 → T13”使用广州塔地铁站至体育西路地铁站，并明确要求分享到本人钉钉文件助手。启动前请确认目标是自己的文件助手，并保持手机连接及钉钉登录；路线读取不完整或收件会话无法核对时，程序停止而非猜测。结果未知且本次记录具有发送时会话名称和消息摘要时，可使用“仅核查钉钉发送结果”，不重新发送。旧版已发送记录如果没有这些摘要，需要本人手工核对，不能用事后猜测的摘要补记。

## 适用边界

- 会话绑定使用发送确认框里本人**显示名**的 SHA-256 摘要，用于比较前后界面，不是钉钉账号的稳定 UID。切换到具有相同显示名的其他账号时，系统无法通过这一摘要区分账号，因此不能把显示名匹配当作身份认证。摘要本身也可能因显示名可猜测而被反推，不应作为脱敏凭据公开。
- 查询标记用于关联本轮正文与当前任务，降低误认旧消息的风险；它不提供抗伪造证明。用户或其他程序如果事先在本人会话中人为构造完全相同的正文和标记，仅凭该界面证据无法排除这种情况。
- 自动定位依赖受支持的钉钉原生页面结构；联系人或确认框出现歧义、全文被截断、状态不可读、设备连接异常等情况会停止或返回未知。手机必须登录钉钉并开启 Demo 无障碍服务；不要求加入钉钉开放平台或使用钉钉 API。
- 分享内容包含用户查询路线的乘车站点及行程概况。仅根据用户明确请求执行；不要把真实截图、界面树或私人消息提交到仓库。
